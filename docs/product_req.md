# Clothing Marketplace Monitor — Product Requirements

## 1. Product Vision

Система мониторинга объявлений преимущественно б/у одежды на маркетплейсах, которая автоматически ищет новые объявления по пользовательским фильтрам и отправляет подходящие варианты пользователю в Telegram.

## 2. Problem

Поиск подходящей одежды на маркетплейсах требует регулярного ручного мониторинга нескольких площадок.

Пользователь может:

- не заметить подходящее объявление;
- найти его слишком поздно, когда товар уже продан;
- тратить значительное количество времени на повторение одинаковых поисков;
- быть вынужденным вручную отслеживать несколько маркетплейсов с разными интерфейсами, валютами и наборами фильтров.

Особенно это критично для выгодных или редких объявлений, которые могут быть доступны ограниченное время.

Система должна убрать с пользователя необходимость самостоятельно заниматься постоянным поиском.

Пользователь один раз задаёт критерии интересующих его вещей, после чего система регулярно проверяет доступные маркетплейсы и уведомляет его о новых подходящих объявлениях.

Таким образом, пользователь тратит время только на:

1. оценку найденного объявления;
2. принятие решения о покупке;
3. непосредственно покупку товара.

Сам поиск и регулярный мониторинг площадок выполняются автоматически.

## 3. Goals

Основные цели продукта:

1. Автоматизировать регулярный поиск одежды на нескольких маркетплейсах.
2. Уменьшить вероятность того, что пользователь пропустит интересное объявление.
3. Максимально сократить время между появлением объявления и уведомлением пользователя.
4. Позволить использовать одинаковые критерии поиска сразу для нескольких площадок.
5. Предоставить единое место получения результатов — Telegram.
6. Сделать подключение дополнительных маркетплейсов относительно простым по мере развития продукта.

## 4. MVP Scope

В MVP входят:

- Telegram-бот как основной пользовательский интерфейс;
- интеграция с двумя маркетплейсами;
- возможность добавления поисковых правил;
- возможность выбора одной или нескольких площадок для конкретного правила;
- автоматический периодический поиск;
- фильтрация объявлений;
- нормализация цен между площадками с разными валютами;
- определение новых объявлений;
- отправка новых подходящих объявлений пользователю;
- хранение информации, необходимой для предотвращения повторных уведомлений.

### Search filters

В MVP поисковое правило должно поддерживать:

- один или несколько брендов;
- одну или несколько категорий одежды;
- один или несколько размеров;
- максимальную цену;
- одну или несколько площадок.

Если площадки явно не выбраны, поиск выполняется по всем доступным для данного правила площадкам.

## 5. User Scenarios

### US-001 — Create Search Rule

Пользователь хочет создать новое правило для автоматического поиска объявлений.

1. Пользователь открывает Telegram-бота.
2. Выбирает действие «Создать правило».
3. Выбирает одну, несколько или все доступные площадки.
4. Вводит один или несколько брендов через запятую.
5. При необходимости указывает категорию одежды.
6. При необходимости выбирает один или несколько размеров из предложенных вариантов.
7. Указывает максимальную цену.
8. Система показывает итоговые параметры правила.
9. Пользователь подтверждает создание правила.
10. Система сохраняет правило как активное.
11. Правило начинает использоваться в последующих циклах автоматического мониторинга.

Обязательные параметры:
- минимум одна площадка;
- минимум один бренд;
- максимальная цена.

Необязательные параметры:
- категория одежды;
- размер.

Если категория не указана, правило применяется ко всем категориям.

Если размер не указан, правило применяется ко всем размерам.

Результат: создано активное поисковое правило.

---

### US-002 — View Active Search Rules

Пользователь хочет посмотреть настроенные активные поисковые правила.

1. Пользователь выбирает действие «Активные правила».
2. Система получает активные правила пользователя.
3. Каждое правило отображается отдельным Telegram-сообщением.
4. В сообщении отображаются основные параметры правила:
   - площадки;
   - бренды;
   - категория, если указана;
   - размеры, если указаны;
   - максимальная цена.
5. Для каждого правила доступны действия:
   - «Редактировать»;
   - «Отключить»;
   - «Удалить».

Результат: пользователь видит все активные поисковые правила и доступные действия над ними.

---

### US-003 — Edit Search Rule

Пользователь хочет изменить существующее поисковое правило.

1. Пользователь открывает список поисковых правил.
2. Выбирает действие «Редактировать» у необходимого правила.
3. Система запускает процесс настройки правила заново, используя текущие параметры как существующие значения.
4. Пользователь изменяет необходимые параметры:
   - площадки;
   - бренды;
   - категорию;
   - размеры;
   - максимальную цену.
5. Система показывает итоговую версию изменённого правила.
6. Пользователь подтверждает изменения.
7. Система сохраняет новые параметры правила.

Результат: существующее поисковое правило обновлено и последующие циклы мониторинга используют новые параметры.

---

### US-004 — Disable Search Rule

Пользователь хочет временно прекратить мониторинг по определённому правилу без его удаления.

1. Пользователь открывает список активных правил.
2. Выбирает действие «Отключить».
3. Система переводит правило в неактивное состояние.
4. Правило больше не участвует в автоматическом мониторинге.

Результат: правило сохранено, но временно не используется для поиска.

---

### US-005 — View Inactive Search Rules

Пользователь хочет посмотреть ранее отключённые поисковые правила.

1. Пользователь выбирает действие «Неактивные правила».
2. Система получает неактивные правила пользователя.
3. Каждое правило отображается отдельным Telegram-сообщением.
4. Для каждого правила доступны действия:
   - «Активировать»;
   - «Редактировать»;
   - «Удалить».

Результат: пользователь видит все сохранённые неактивные правила.

---

### US-006 — Activate Search Rule

Пользователь хочет снова включить ранее отключённое правило.

1. Пользователь открывает список неактивных правил.
2. Выбирает действие «Активировать».
3. Система переводит правило в активное состояние.
4. Правило снова начинает участвовать в последующих циклах мониторинга.

Результат: правило снова активно.

---

### US-007 — Delete Search Rule

Пользователь хочет полностью удалить поисковое правило.

1. Пользователь открывает список активных или неактивных правил.
2. Выбирает действие «Удалить».
3. Система удаляет правило.
4. Правило больше не отображается пользователю и не участвует в мониторинге.

Результат: поисковое правило удалено.

---

### US-008 — Receive Matching Listing

У пользователя есть одно или несколько активных поисковых правил.

Система автоматически выполняет мониторинг маркетплейсов с заданной периодичностью.

1. Система получает новые объявления с поддерживаемых площадок.
2. Найденное объявление проверяется на соответствие активным поисковым правилам.
3. Если объявление соответствует правилу и ранее не отправлялось пользователю, система формирует Telegram-уведомление.
4. Пользователь получает сообщение с найденным объявлением.

Telegram-карточка должна содержать:
- фотографию товара;
- название объявления;
- бренд;
- цену;
- ссылку на оригинальное объявление.

Результат: пользователь получает информацию о новом подходящем объявлении без необходимости самостоятельно проверять маркетплейс.

---

### US-009 — Open Original Listing

Пользователь хочет подробнее изучить найденное объявление.

1. Пользователь получает Telegram-карточку объявления.
2. Нажимает на ссылку на оригинальное объявление.
3. Открывается страница объявления на соответствующем маркетплейсе.

Результат: пользователь может оценить объявление и при необходимости продолжить покупку непосредственно на маркетплейсе.
